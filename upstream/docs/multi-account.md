# 桌面多账号与消息核查

侧栏的账号列表用于切换当前视图。添加账号不会替换其他账号的 Cookie；退出账号会停止该账号的自动任务、取消排队任务并移除其凭证，历史记录保留。凭证仍可能被 B 站主动撤销，此时只需重新登录相应账号。

来源与活动资料共用一份，各账号分别保存参与、预约、归档、预选池、参与设置、自动参与、开奖结果和清理状态。同账号任务串行排队，不同账号可并行，网络请求仍统一限速。共享来源任务使用全局队列。

## 清理前消息确认

每次开奖核验与清理都会检查私信和 @。首次纳入现有未读，此后按消息标识和游标检查新增，手机已读不影响新增识别。仅排除本人发出的私信和平台 `msg_source=8/9/10/11` 标记的自动回复；未知来源继续呈现。

消息接口有非官方、可能变化的字段依赖，解析不完整、分页异常和接口失败均阻断清理，保留上次完整检查的游标。此版本的验证使用模拟响应，没有使用真实账号进行领奖消息或删除取关测试。

待确认消息或检查失败会暂停该账号清理。用户可确认消息无关，或关联已参与活动并确认中奖。确认中奖会保留活动；与官方名单冲突时保留冲突提示。没有消息不代表未中奖。

暂停状态持久保存。处理全部消息后，需要手动重新执行清理，后台维护不会自动解除暂停。重新执行及每个删除、取关动作前仍会检查消息。读取接口与用户确认分别记录，不调用平台已读写接口。

## 实现边界

- 请求通过 `X-Account-UID` 指定账号；SSE 与图片等不能设置头的请求可用 `account_uid` 查询参数。多个账号存在时，账号 API 不允许依赖隐式全局选中账号；单账号旧调用保留兼容。`none` 表示未选择账号。
- `AccountContext` 通过 ContextVar 绑定请求和任务，线程显式复制上下文。后台任务在创建时固定 UID；切换界面不修改进程级账号。
- `/api/accounts` 返回账号列表；`POST /api/accounts/login` 创建独立扫码会话，`expected_uid` 可限定重新登录账号。对应会话提供状态、二维码和取消接口；`POST /api/accounts/{uid}/logout` 退出指定账号。
- `/api/maintenance/messages` 返回检查和待确认状态；`POST /api/maintenance/messages/resolve` 接收 `key`、`resolution`（`irrelevant` / `won` / `pending`）及中奖时的 `dynamic_id`。逐条确认不影响并发到达的新消息。
- SQLite schema 升至 6。新增 `account_state` 按 `(uid, key)` 保存账号资料、活动状态、消息检查点及确认结果；原有按 UID 保存的参与和清理表保持不变。凭证位于 `config/accounts/<uid>/cookies.txt`。
- 升级先备份 SQLite（包括 WAL 提交页），迁移凭证前生成受权限保护的 `cookies.pre-multi-account.txt`。迁移幂等；原账号继承可确认归属的数据，未知归属记录保留原位。新增账号默认关闭自动参与。
- 云端仅同步全局活动基础资料，按活动 ID 去重；无需绑定 B 站 UID。参与、筛选、归档、预选池、清理和任务记录均保留本机，凭证不上传。服务器每分钟清理开奖结束超过 7 天的资料，不影响本机历史。

## 验证方式

新增后端隔离测试覆盖账号凭证、线程上下文、活动状态、归档、设置、迁移、并发与串行排队，以及多页消息、手机已读、自动回复、失败游标、人工确认及清理阻断。

前端测试覆盖请求固定 UID、迟到响应丢弃；模拟双账号检查验证切换后筛选恢复、消息隔离且无脚本异常。
# 归档规则补充

自动归档先核对开奖时间：已公布的开奖时间仍在未来时，即使发布时间超过 7 天或其他历史窗口，也不移出活动库。仅凭发布时间不能判断活动已结束；未知开奖时间也不走发布年龄归档。手动“移出”仍然有效，并单独记录原因。

历史误归档通过 `scripts/repair_publication_archives.py` 显式修复，不在启动时批量恢复。修复要求原始清理报告中的活动 ID、归档批次时间与当前记录完全一致，且活动仍有效、开奖时间在未来；手动移出、再次归档、云端变更及其他账号的不同归档记录均保留。默认只预览，`--apply` 前自动备份数据库；重复运行不会重复恢复。
