# 活动资料与转发关联同步

同一应用账号下 Windows、Mac 共用活动资料库，活动 ID 去重；开奖结束超过 7 天的活动基础资料自动清理。

另行长期保存 `(B站 UID, 原活动 ID, 本人转发 ID)`。账号分别记录，同活动同 UID 的不同转发 ID 全部保留，不采用最后写入覆盖。仅上传已记录/已确认的转发关联，不上传 Cookie、任务、筛选、归档、消息及清理授权。资料清理不会删除转发关联。

设备每轮仅上传未确认发送的记录，下载按服务端递增游标分页，整页校验并提交本地数据库后推进游标；重复提交幂等。换机登录同一应用账号后同步，在新设备登录相应 B站 UID 即可按该 UID 使用关联记录。

记录是历史证据，不表示所有参与步骤已经完成，也不授权删除或取关。参与前只读核验转发的作者、原活动 ID 和当前存在性；核验失败暂停，不盲目再转发。关注来源、消息确认、清理许可继续留在本机。同步不是分布式执行锁，两台机器不应同时操作同一 B站 UID；不同 UID 可以分别运行。

服务端部署前备份数据库，新增 relay_reposts 表，旧客户端仍能同步基础资料。客户端 schema v7 自动备份旧库后添加 synced_reposts 表。Mac 补丁需在源码工程中应用并重新构建 App，不能直接覆盖 App 内零散 Python 文件。
