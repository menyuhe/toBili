# 本机定时任务与 Mac 共用方案

Windows 已实现；Mac 共用 Python 调度器、账号配置和前端，不依赖服务器任务调度。Mac 实机尚未构建验证。

在定时任务面板分别选择 B站话题发现、一键更新活动链接、监控用户动态、刷新任务状态和预选池参与。各项周期可设为 5 至 10080 分钟。保存仅更新当前账号计划；启动调度后按周期执行，忙碌时延后。配置修改后重新计时；关闭软件后不运行，重启恢复此前已开启账号的调度，不补跑错过的次数。

7×24 挂机默认关闭。开启后强制启用刷新与参与，刷新使用挂机刷新周期，参与沿用预选池周期；直接遍历当前账号活动列表内的所有可参与活动，不要求加入预选池，也不受预选池容量或暂停影响。每账号最近 60 分钟参与尝试上限默认 20 个，可设置 1 至 500 个；失败、超时计入，额度持久化，重启不清零。达到上限等待后续周期，额度恢复后继续处理未参与项。已归档、已参加和不可参与活动不纳入，挂机参与失败或取消后独立暂停，可在定时任务面板手动恢复；恢复参与不会解除消息清理阻断。

开奖清理周期可独立配置；挂机模式复用 maintenance_cycle，不调用手动解除清理阻断的接口。需在清理设置中启用对应操作，消息待确认、检查失败、中奖、保留名单、关联未核验和宽限期均继续阻断清理。处理消息后仍需用户手动重新启动清理。

所有配置、任务记录及账号状态仅保存本机。多账号的共享来源使用全局队列，同一种来源更新按周期去重；账号状态刷新与参与保持独立。网站仅共享活动基础资料，服务器接口与数据库无需改动。

## Mac 后续验证

源码包携带同一配置模型、调度代码、前端和模拟测试。在 Mac 上运行后端测试、前端类型检查与构建，再构建 app；实机检查系统睡眠唤醒后的周期延后、关闭重开恢复、账号切换与消息阻断。保持系统休眠时不执行，不添加系统服务或跨设备接管。
