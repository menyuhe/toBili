# toBili

toBili 是本机运行的 B 站抽奖活动管理工具：发现奖品、加入待参与、按账号定时参与、查看消息、核验开奖及清理。支持一台电脑管理多个账号。

## 普通版与 Pro

| 功能 | toBili 开源版 | Pro 私有插件 |
|---|---|---|
| 本机多账号、挂机中心、独立定时任务 | 有 | 使用同一核心 |
| 话题、UP 合集、UP 动态、关注流 | 有 | 使用同一核心 |
| 奖品识别、人工修订、开奖时间推算、UP 黑名单 | 有 | 黑名单另支持设备间同步 |
| 消息复核、账号隔离的 B 站窗口、开奖与清理 | 有 | 使用同一核心 |
| 公开活动目录只读导入 | 有 | 有 |
| 编稿室、文章模板、富文本及素材导出 | 无 | 有 |
| 跨设备修订审批、账号执行设备归属、异机恢复 | 无 | 有 |

本仓库及普通版发行包不包含 Pro 实现、私有服务、账号数据或连接密钥。普通版的账号锁仅作用于本机，不协调多台电脑的真写归属。

## Windows 桌面版

将 `toBili.exe` 放到有写入权限的独立文件夹，双击启动。Windows 需要 Microsoft Edge WebView2 Runtime；缺少时程序会提示。主界面使用内置窗口，关闭主窗口会结束该进程的服务。需要关窗口后仍挂机时，以 `toBili.exe --tray` 启动托盘模式，再从托盘打开界面；从托盘退出才会停止后台服务。

- 数据保存在 EXE 同级的 `data/`；主题偏好保存在该数据目录对应的窗口配置中。
- 首次扫码登录后，可在右上角继续添加账号；新增账号不会自动开启定时任务。
- 「挂机中心」查看所有账号当前事项、下一事项、倒计时和最近记录。
- 「发现与参与 → 订阅源」添加话题、UP 合集、UP 动态或关注流；按需设置更新周期。
- 「发现奖品」筛选、修改奖品、加入待参与或标记不参加。参与节奏在设置中配置。
- 顶栏「定时任务」为当前账号选择功能、周期及参与范围；真实参与可能发出转发、评论等操作。
- 「开奖与消息」复核结论、看消息及清理。清理检查不会自行删除转发；删除需在清理清单执行。
- 消息的「未看」是本机列表状态；B 站通知中心的未读数字独立显示，可用对应账号窗口打开查看。

普通版和 Pro 应使用不同的目录与端口。默认优先使用端口 8811，占用时自动选择空闲端口；也可显式指定：

```powershell
.\toBili.exe --port 8812
```

升级前退出程序、备份整个 `data/`，再替换 EXE。数据库自动升级，当前结构版本为 14。Windows 凭据使用当前系统用户的 DPAPI 加密，复制数据到另一台电脑或另一个 Windows 用户后需要重新登录；不要把数据目录当成可公开分享的便携配置。

## 公开目录与服务器

入口：**发现与参与 → 订阅源 → 公开目录**。匿名按批读取奖品资料与后续修正，跳过已过期与已屏蔽 UP，保留本机手动修改。不会导入其他人的参与记录、自动任务或写权限。

- [公开奖品页面](https://tobili.4wdo.cn/public/)
- [修订读取接口](https://tobili.4wdo.cn/public/v1/catalog?limit=10)：`after` 是修订序号，`limit` 最大 100；返回 `items`、`next`、`more`。
- `/pro/` 为私有插件服务，普通版不连接它。

读取不携带 B 站 Cookie 或 Pro 密钥，普通版不自动上传。目录不可用时可继续使用自己的订阅源。源码包含 [独立公开目录服务](../../services/public_catalog/README.md)，部署时应使用自己的发布密钥。

## LLM 与数据

在「管理 → 设置 → 模型接入」填写自己的兼容接口、模型与密钥。未配置模型时仍可管理奖品、人工修订与执行其他功能。模型用于识别正文或图片中的奖品和参与要求；开奖时间结合发布时间及原文证据推算，没有依据保留未知，人工修改不会被自动扫描覆盖。

调用模型会将待识别的内容或图片交给配置的模型服务。登录凭据、模型密钥、通知密钥保存在本机保险库，不随公开目录上传。模型无固定调用次数额度，但保留请求排队、失败冷却与网络超时处理。

## 源码运行与打包

需要 Python 3.12+、uv 和 Node.js 20+。源码包不带个人数据、虚拟环境、node_modules 或 Git 历史。

```bash
uv sync --locked
cd ui
npm ci
npm run typecheck
npm run build
cd ..
uv run tobili serve --port 8848
```

浏览器打开 `http://127.0.0.1:8848`。开发前端可运行 `npm run dev`，API 默认代理到 8848。源码数据默认位于 `./data`，可用 `TOBILI_HOME` 指定；不要指向正在运行的 Pro 数据目录。

Windows 构建普通版：

```bash
uv run python tools/build_desktop.py
uv run python tools/source_release.py
```

分别生成 `dist/toBili.exe` 与 `dist/toBili-source.zip`。构建脚本使用当前前端产物，修改界面后应先重新执行 `npm run build`。源码打包前自动执行发行内容检查，不打包整个工作文件夹。

## 验证与参与开发

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest --cov
uv run python tools/similarity_check.py
uv run python tools/release_check.py
```

模拟测试不使用真实账号参与、发消息或删除转发。网络限流、接口变化、账号失效和长时间运行仍需在实际环境观察；功能测试通过不等于平台操作永远成功。参加操作按账号串行，失败或未知结果不会盲目重发。截止不等于未中奖，删除线上转发不可恢复。
