# toBili 使用手册

面向安装包用户。按「登录 → 找活动 → 参与 → 收尾」的顺序读，遇到问题直接跳到[故障排查](#故障排查)。

---

## 界面结构

窗口左侧是侧栏，右侧是内容区。

| 位置 | 内容 |
| --- | --- |
| 侧栏导航 | 概览 / 数据源 / 活动 / 设置 四个页面 |
| 侧栏账号区 | 账号列表、扫码登录、退出登录、刷新账号 |
| 右上角「定时任务」 | 调度面板：周期配置、挂机模式、启动/停止调度 |
| 右侧「任务日志」 | 当前与最近任务的实时日志，可查看每一步走到哪 |
| 底部系统区 | 靠边收起侧栏、切换夜间模式 |

## 登录与多账号

1. 点侧栏 **扫码登录**，用 B 站 App 扫二维码；二维码过期会提示刷新。
2. 想再挂一个号，点账号列表右上角的 **＋ 添加** 再扫一次。**原有账号不会被替换或退出。**
3. 点账号列表里的任意账号即可切换视图；活动统计、任务日志、消息提醒都会换成该号的。

每个账号各自独立保存：

- 登录 Cookie（本机 `config/accounts/<uid>/`）
- 参与记录、预约、归档、预选池
- 参与文案与清理设置
- 定时计划与挂机上限
- 私信 / @ 核查状态

**退出某个账号**会停止它的自动任务、取消它的排队任务并删除凭证，历史记录保留，其他账号不受影响。

> 凭证也可能被 B 站主动撤销。某天发现该号任务都提示需要登录，重新扫码即可，数据不会丢。

## 数据源：三路找活动

### B 站抽奖发现（话题）

直接读 B 站话题动态，不依赖第三方数据库。

- **更新话题**：检查最新页，按已有进度增量续采。
- **补齐近 7 天**：沿历史位置持续往前读，直到整页早于 7 天或没有下一页。可随时取消，再次点击从上次位置继续。
- 面板上的「3 / 4 个话题」表示已把几个话题的分页走完，不是完成度百分比；接口不提供总页数，所以不显示预计剩余时间。

### UP 合集

- 内置 9 个常用合集（其中 2 个为备用源），可 **添加 / 修改 / 移除**，也可以新增别人的合集（填 UP 的 MID）。
- 每个源最多提取最新 20 条活动链接，只处理新链接，历史记录全部保留。
- **更新此源**：只更新这一个源，日常推荐。
- **一键更新**：串行更新全部合集，请求更猛，适合空库首次灌库或隔几天补一次。

### 监控用户动态

- 在监控名单里填 **用户 MID**（空间页地址里那串数字）即可加入。
- **更新监控用户动态**：按时间窗口拉这些用户的转发动态，补合集没收录的活动。
- 默认回溯约 10 天，面板会显示监控人数、上次同步与下次窗口。

> 三路都只是「发现渠道」，不是全站抽奖全集；没被话题覆盖、也没人转发的活动，需要你把对应 UP 加进合集或监控名单。

## 活动与参与

活动页顶部有三个标签：**活动列表**、**预选池**、**开奖与清理**。

### 活动列表

| 控件 | 说明 |
| --- | --- |
| 类型 | 全部 / 互动抽奖 / 转发抽奖 / 预约抽奖 |
| 状态 | 全部 / 未参加 / 已参加 / 已结束 |
| 排序 | 默认 / 按热度升 / 按热度降 |
| 即将开奖 | 只看已参加且约 3 天内开奖的 |
| 搜索 | 按奖品名称关键字 |
| 参与 | 行内执行完整参与流程 |
| 刷新任务状态 | 回查已有活动的参与/开奖结果，不拉新链接 |

- 互动抽奖会依次做：点赞 → 关注 → 收藏 → 转发 → 评论；已完成的项自动跳过，不会把状态点反。
- 转发抽奖会先取正文（需 LLM 解析奖品与开奖时间），再关注、转发、评论。
- 预约抽奖只做关注与预约。
- **充电抽奖自动跳过**，避免误扣费。
- 未参加且已过期的活动会从列表隐藏，历史仍在本地；活动可手动「移出」到已归档。

### 预选池

- 把想参与的活动加入池子，按加入顺序逐条执行，上限 200 条。
- 单项可暂停；定时任务只跑未暂停的项。
- 已归档的活动不会出现在可执行候选里。

### 参与文案

设置页里配置，用于转发与评论：

- 支持固定文案，或「随机借用」该活动下已有的评论（不足时用兜底文案）。
- 建议格式：`@好友昵称 + 一句话`，例如 `@小明 好运连连！`
- 最长 233 字。

## 定时任务与挂机

右上角 **定时任务** 是调度面板，配置 **按账号保存**。

| 任务 | 默认周期 | 作用 |
| --- | --- | --- |
| B 站话题发现 | 180 分钟 | 拉话题最新动态 |
| 一键更新活动链接 | 180 分钟 | 扫全部合集 |
| 更新监控用户动态 | 180 分钟 | 扫监控名单 |
| 刷新任务状态 | 180 分钟 | 回查开奖与参与结果 |
| 预选池参与 | 5 分钟 | 执行预选池 |
| 挂机刷新 / 开奖清理 | 180 / 30 分钟 | 挂机模式下生效 |

规则：

- 周期范围 **5 分钟 ~ 7 天**，可单独开关每一项。
- 勾选 **7×24 挂机模式** 后，会自动「刷新来源 → 参与活动库里所有可参与项 → 开奖核查与安全清理」。
- **每小时参与上限** 按最近 60 分钟的尝试次数计数（失败也计入），默认 20，可设 1~500；达到上限自动等待，重启不清零。
- 失败或人工暂停后**不会自动继续**，需要在面板里手动恢复。

> 保存计划不会立刻执行；要点 **启动调度** 才开始计时。**关闭软件后不会执行**，这是刻意设计——不在后台偷偷跑。

撞车保护与停止：

- 已有任务在跑时，到点的任务会**延后**，不会无脑并发。
- **停止调度**只停计划，**不会取消**正在进行的那次参与。

## 开奖核查与安全清理

在「活动 → 开奖与清理」里，清理默认**关闭**，需要主动开启并核对设置。

流程：

1. **核查消息** —— 检查该账号的私信与 @。首次纳入现有未读，之后按消息标识与游标只看新增；手机上已读不影响识别。
2. **人工确认** —— 出现可疑消息时暂停该账号清理，你可以标记：
   - 与领奖无关 → 继续
   - 已中奖 → 保留该活动
   - 暂不确定 → 保持暂停
3. **等待期** —— 确认未中奖后仍有 **24 小时**等待，避免手快。
4. **分批执行** —— 每轮最多删除 **20 条转发**、取关 **20 位 UP**，按开奖时间从旧到新处理。

硬约束：

- 保留名单中的 UP、既有关注、待确认消息都不会因批次优化被绕过。
- 同一轮内消息核查结果复用 5 分钟，减少重复请求。
- 消息解析失败、分页异常、接口报错都会**阻断清理**并保留上次完整检查位置，不会把失败当成「没有消息」。
- **没有中奖消息 ≠ 未中奖**，重要活动建议自己再核对一次。

## 通知

设置页可开启两类通道：

| 通道 | 说明 |
| --- | --- |
| 桌面音频 | 任务结束或事件触发时本机响铃 |
| 钉钉机器人 | 填 Webhook（可选加签密钥），支持自定义前缀 |

覆盖事件：**中奖**、**@ 未读增加**、**登录失效**、**任务失败**、**清理汇总**。推送失败会进入发件箱排队重试，不影响业务结果。

## LLM 配置

- 用于解析**转发抽奖**正文中的奖品与开奖时间；互动 / 预约抽奖不消耗模型。
- 兼容 OpenAI 接口格式（推荐 DeepSeek）。**接口地址为必填项**，必须是 `http(s)://` 开头。
- 填好 API Key 与模型名后先点 **保存配置**，再点 **测试连接**；测试通过后解析功能才可用。

没有可用模型时，转发抽奖仍会入库，但奖品与开奖时间可能显示为「未公布」。

## 数据与备份

| 平台 | 默认数据目录 |
| --- | --- |
| Windows | 程序旁的 `user-data/` |
| macOS | `~/Library/Application Support/toBili/` |
| 自定义 | 环境变量 `BINGGO_HOME` 指定的路径 |

目录里有：活动库（SQLite）、参与记录、账号 Cookie、日志、诊断信息。

- **备份**：退出程序后整目录复制即可；迁移到新机器时放回同一位置，或让 `BINGGO_HOME` 指向它。
- **升级**：先退出程序 → 备份数据目录 → 替换程序文件 → 保留数据目录。
- **诊断**：概览页「导出诊断包」会生成脱敏信息（不含 Cookie 与 API Key），报问题时附上它比自己描述更快。

## 故障排查

| 现象 | 排查方向 |
| --- | --- |
| 窗口打不开 / 一闪而过 | 检查是否已安装 Microsoft Edge WebView2 运行时；查看数据目录下 `desktop-error.log` |
| 提示需要登录 | 该账号 Cookie 被撤销，重新扫码；其他账号不受影响 |
| 定时任务不执行 | 是否点了「启动调度」；软件是否被关闭；当前看到的计划是否属于这个账号 |
| 任务一直延后 | 已有任务在跑，或该账号 1 小时内达到参与上限，等下一轮即可 |
| 拿不到新活动 | 数据源里对具体合集点「更新此源」；确认监控名单里的 MID 正确 |
| 转发抽奖没有奖品信息 | LLM 未配置或测试未通过；配好后点「刷新任务状态」重试 |
| 清理不动 | 该账号有未确认消息、清理未开启、或仍在 24 小时等待期内 |
| 重复启动没反应 | 单实例保护生效，已有窗口在运行；到任务栏找一下 |

更多实现细节见 `upstream/docs/`：`console.md`（控制台逐页说明）、`multi-account.md`（多账号与消息核查）、`direct-lottery-discovery.md`（话题采集）、`pipeline-redesign.md`（数据管道）。
